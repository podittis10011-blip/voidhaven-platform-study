## 0. 本轮定位

VH-04 要回答的是三件容易被混为一谈的事：

| 问题 | 机制 | 本轮要能说清的边界 |
|---|---|---|
| 同一个请求被发了两次，会不会产生两条数据？ | `Idempotency-Key` + `idempotency_records` | 幂等键的作用域、请求体哈希、在途租约、敏感结果不可回放 |
| 两个人同时改同一条数据，谁的改动会丢？ | `If-Match` + JPA `@Version` + 悲观锁 | 三道防线各挡什么、冲突怎么变成可解释的 409 |
| 多个进程/副本同时在跑，谁说了算？ | MySQL 行锁、`GET_LOCK`、租约列、唯一约束 | 为什么不用 `synchronized`、为什么限流计数要独立事务 |

本轮不改 `learning-state.yaml`，不改正式源码，不新增业务功能。

## 3. 一句话结论（读完再回来看）

```text
限流（能不能发） → 幂等（是不是同一次） → 版本（是不是基于最新状态） → 业务事务
   独立事务            独立事务              业务事务内比较           悲观锁 + @Version 兜底
```

四层各自独立提交或独立回滚，`RetentionService` 负责清理前三层留下的记录。
